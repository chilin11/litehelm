# LiteHelm v0.2 implementation contract

Scope: six low-overhead features; no vendor-specific networking mentions. Keep existing HTTPS+Bearer, request serialization, lifecycle invalidation, mutation confirmations, dark native UI. No new background threads/timers server-side beyond handling requests. No client background polling; dashboard alone 5s system polling. No automated queries of every saved host.

## Android local features

- Multi-host encrypted profiles (id/name/origin/token) with one active id; migrate v1 single config without loss. Store profiles and per-profile service favorites with Keystore AES-GCM, never plaintext tokens. Add host chooser in header/dashboard and settings, add/edit/delete saved profiles with explicit delete confirmation. New/edit credentials validated before replacing saved profile. Switching host invalidates all system/process/service/tool data and rates, closes dialogs, rejects late responses; no switching while a write is in flight. Active host name visible in all mutation confirmation sheets. Do not alter saved profile if validation fails/cancelled. Rotation retains drafts; system restart retains saved profiles/active id/favorites. Favorites use stable profile ids, not global shared service names.
- Service detail favorite toggle and favorites section on dashboard; pressing favorite loads fresh service state/details before actions, no services fetch each 5s. Cached favorite state must not imply current health. Use existing service confirmation rules; cap favorites 12 per host.
- Logs local search, match count/filter, copy visible/all with Android clipboard warning; preserve fetched original logs, cap64KiB, refresh manual, no polling. Clipboard copies only on explicit tap. Names/full target shown.

## Tools API (new optional capabilities, old server 404 clearly says update server)

Tool menu from dashboard or service page, no automatic fetching until chosen. Tools are one-shot reads with manual refresh, local search where useful. Existing `read` and `mutate` handling must retain same connection+generation safety. If leaving tools or sheet, invalidate its late response without losing the main page. Choose simple readable scroll sheets/list native Java Views, retain bottom nav.

- `GET /api/v1/ports`: `{ "supported":true,"ports":[{"protocol":"tcp","address":"0.0.0.0:80","pid":123,"process":"nginx","service":"nginx.service"}],"truncated":false }`. Each listener/process separate row; unknown pid=0/name empty, show unavailable. Only listening TCP and UDP bound sockets, no connection history. If ss missing: supported=false, ports=[], message. Local search address/process/service. Read only, no arbitrary command UI.
- `GET /api/v1/timers`: `{ "supported":true,"timers":[{"name":"backup.timer","description":"Backup","active_state":"active","sub_state":"waiting","next_run":"Sat 2026-10-17 12:00:00 UTC","last_run":"...","unit":"backup.service","can_run":false}],"truncated":false }`. Non-systemd supported=false. Manual trigger button only if can_run; confirmation complete host/timer/unit and no duplicate POST. `POST /api/v1/timers/{name}/run` body `{ "confirm":"backup.timer" }`, server resolves triggered service freshly, checks exact whitelist `LITEHELM_RUN_TIMERS` and protected units; `{ok:true,message:"Task start accepted"}` means accepted, do not claim job completed. No editing cron/script/timers. Cron fallback not included, label systemd 定时任务 explicitly.
- `GET /api/v1/disks`: `{ "disks":[{"mountpoint":"/","device":"/dev/vda1","filesystem":"ext4","total":123,"used":42,"available":81,"inodes_total":100,"inodes_used":20}],"scan_roots":["/var/log","/var/cache"],"truncated":false }`. Local filesystems only, no remote mount statfs. Fields in bytes, inodes counts; 0 inode total -> unavailable, not 0%. Scan roots server-controlled LITEHELM_SCAN_ROOTS defaults /var/log,/var/cache; client chooses one returned root (no arbitrary path input). `POST /api/v1/disk-scan` body `{ "path":"/var/log" }` returns `{ "path":"/var/log","bytes":123,"files":12,"entries":[{"name":"nginx","bytes":100,"files":3}],"partial":true,"reason":"time/entry/depth/permission limit","elapsed_ms":200,"metric":"logical_bytes" }`. Manual confirm says read-only bounded directory scan may cause disk IO, only on tap. logical bytes lower-bound when partial; not reclaimable or physical allocation, no delete. Server limits 2s / 10000 entries / depth6, no symlinks or crossing filesystem, one scan at a time and 15-second cooldown; may return429. Client render top20 entries, partial flag and explanation prominent. Refresh disks does not auto-rescan. No background tail/scans.
